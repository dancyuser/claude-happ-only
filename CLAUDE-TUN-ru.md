# Claude только через выбранный TUN

Для этой задачи **IP сервера не нужен**. Режим `TunOnly / InterfaceOnly` устанавливает постоянные WFP-запреты для EXE Claude: соединения разрешены только с локальным интерфейсом выбранного TUN. Если Windows выбирает Wi-Fi, Ethernet, другой VPN или loopback-прокси, соединение блокируется. IPv6 по умолчанию полностью блокируется для выбранных EXE. Ограничения сохраняются после завершения установщика и действуют при запуске обычным ярлыком.

## Установка

1. Установите Claude и Happ, подключите нужный VPN и включите TUN.
2. Закройте Claude. Распакуйте комплект целиком и запустите `Install-Claude-TUN.cmd` обычным пользователем. В `Install.cmd` это также пункт **3 — Claude TUN Only**.
3. Мастер найдет установленный пакет Claude, его EXE, существующий кеш Claude Code и отдельный CLI, если он установлен по стандартному пути. Он покажет найденный TUN, его GUID, локальный IP и список защищаемых файлов. Подтвердите `y`, затем UAC.
4. Успех установки — `TESTED`, `Ready=true` в отчете. При неудачном сетевом тесте ограничения остаются, но ярлык проверенного запуска не создается. Мастер не запускает Claude.

Запускайте Desktop через ярлык **Claude - TUN Only**: он добавляет `--no-proxy-server` только Desktop-процессу. Иначе включенный системный прокси на `127.0.0.1` может привести к `ERR_PROXY_CONNECTION_FAILED`: такой обход блокируется правилами TUN. Глобальные настройки прокси установщик не меняет. Профиль хранит явный `DesktopExecutable`, поэтому наличие CLI и других EXE не меняет выбранную программу запуска.

Если активных TUN несколько, мастер попросит выбрать один. Физический адаптер вместо TUN не принимается. Идентификатор сохраняется как GUID; переименование не выбирает другой интерфейс. Для отдельной установки Claude используйте `Setup-ClaudeTun.ps1 -ClaudeExecutable 'C:\Apps\Claude\claude.exe'`.

Посмотреть формируемый профиль без установки:

```powershell
.\Setup-ClaudeTun.ps1 -Preview
```

При повторном запуске мастер обновляет свой профиль `Claude TUN Only` с тем же ProfileId. После обновления Claude/Code на новый путь запустите этот установщик снова, чтобы включить новые EXE. Старый профиль из прежней схемы Claude/Happ не удаляется автоматически: при конфликте установщик остановится и сохранит существующие ограничения.

## Что проверяется

Установка проверяет наличие именно заданных WFP-фильтров, доступ защищенной диагностической копии curl через TUN, отказ при привязке к физическому адаптеру и временный полный запрет для диагностического процесса. DNS проверочных адресов разрешается рабочим процессом заранее: собственный асинхронный DNS curl использует loopback-сокеты, запрещенные строгими правилами. TLS/SNI сохраняют исходное имя сервера; сетевые ограничения не ослабляются.

Отдельный живой тест `tests\Test-TunLive.ps1` проверяет реальную потерю маршрута, административное отключение TUN, TCP/UDP/IPv6 и последующее восстановление. Он выполняется только явно, в административном PowerShell, с параметрами `-TunnelGuid`, `-ReportPath` и `-DisconnectTunnel`. Во время теста VPN временно теряет связь. Он использует отдельные диагностические EXE, затем удаляет только свои фильтры и восстанавливает адаптер/маршруты. Статические тесты его не запускают.

## Границы режима

Привязка к интерфейсу блокирует **обход TUN приложением**. Правила маршрутизации внутри VPN принадлежат самому VPN: если его ядро при активном TUN специально пересылает выбранный домен через DIRECT, одна привязка EXE к TUN этого не отличает. Настройте в Happ VPN-маршрут для Claude. Дополнительный `InterfaceAndCore` доступен в универсальном мастере для известного отдельного ядра и одного известного серверного IP; он влияет на весь трафик этого ядра и для обычной привязки к TUN не требуется.

Схема охватывает перечисленные Windows EXE. Новые пути после обновлений и сетевой трафик внешних служб/виртуальных машин требуют отдельного включения и проверки. Реальная перезагрузка устройства и обновление Claude на новую версию не заменяются проверкой постоянства фильтров в текущем сеансе.
