# Встроенный Claude Code: настройка Happ

Code выполняется отдельным процессом и может не использовать SOCKS-аргумент Electron Desktop. Claude Code документирует HTTP/HTTPS proxy и не поддерживает SOCKS. Требуется HTTP CONNECT на том же разрешенном локальном порту Happ; если его нет, Apply завершится без изменения settings.json. Правила Firewall/WFP ослаблять не требуется.

## Применение на существующей машине

1. Самостоятельно полностью закройте Claude Desktop и Code. Скрипты их не завершают.
2. В Happ оставьте подключенным нужный сервер. Не меняйте Chrome proxy extensions.
3. Откройте обычный Windows PowerShell, не от администратора. Перейдите в папку комплекта и выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Update-CodeSupport.ps1
```

Подтвердите UAC для Fix и затем для CheckOnly. Обновление сохраняет резервную копию пользовательского settings.json, создает штатную резервную копию защиты перед Fix, обновляет защищенные скрипты и заканчивается проверкой CheckOnly. Сам Claude не запускается. При отмене/ошибке возможен частично выполненный ремонт; читайте UPDATE INCOMPLETE и отчеты, не считайте такую установку успешной.

Для проверки начальных шагов без изменений, сетевых проб и UAC используйте `Update-CodeSupport.ps1 -ValidateOnly`. Обычная проверка закрытого клиента не обращается к списку пакетов всех пользователей. Полная проверка пакета и зарегистрированной CoworkVMService выполняется после UAC в Manage-Happ. Не запускайте весь updater от администратора: пользовательские настройки должны записываться в профиль целевого обычного пользователя. При ошибке updater печатает конкретный шаг, ErrorId и стек вызовов.

Пользовательская настройка по умолчанию: `%USERPROFILE%\.claude\settings.json`, либо settings.json в CLAUDE_CONFIG_DIR, если эта переменная установлена в вызывающем процессе. Существующие посторонние настройки сохраняются. Полный исходный файл копируется побайтно.

Добавляется env:

```json
{
  "HTTP_PROXY": "http://127.0.0.1:10808",
  "HTTPS_PROXY": "http://127.0.0.1:10808",
  "ALL_PROXY": "http://127.0.0.1:10808",
  "NO_PROXY": ""
}
```

HTTPS_PROXY использует http://, поскольку соединение с локальным HTTP-прокси обычное, а TLS до целевого сайта проходит внутри CONNECT. Нижнерегистровые конфликтующие варианты этих ключей заменяются каноническими. Системный прокси и постоянные переменные окружения Windows не меняются.

## Проверка и ручной тест

Отдельная проверка пользовательских настроек и HTTP-прокси, без запуска Claude и без UAC:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Configure-CodeProxy.ps1 -Mode Diagnose
```

Ожидаются OverallOK=True, SettingsOK=True, Transport.OK=True, нужная страна и одинаковый IP двух HTTPS-сервисов. Это не доказывает успешный API-запрос Code и отсутствие переопределений в проекте или managed settings.

После успешного Update/CheckOnly пользователь может сам запустить Claude через проверяемый ярлык, открыть новую Code-сессию и выполнить /status, если команда доступна. Proxy должен указывать на http://127.0.0.1:10808. Затем повторить один ранее неработавший запрос. Ранее открытый процесс может сохранять старые настройки.

Повторный WFP-захват должен показать отсутствие прежних внешних попыток Code через FlClashX и соединения Code к Happ. Успешный запрос и отрицательная проверка при недоступности Happ остаются отдельными ручными проверками. Встроенная fault-проверка curl не отключает Happ физически: она перекрывает прокси только тестовому EXE и проверяет, что HTTP/SOCKS и прямой обход не работают.

## Откат пользовательских настроек

В выводе Apply/Update указан BackupId. При закрытом Claude в обычном PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Configure-CodeProxy.ps1 -Mode Restore -BackupId ВАШ_BACKUP_ID
```

Резервные копии находятся рядом с settings.json в happ-proxy-backups. Restore сверяет хеши и отказывается затирать настройки, измененные после Apply. Если файла изначально не было, удаляется только совпадающий с примененной версией файл. Измененные вручную настройки следует объединять с settings.before самостоятельно. Для нестандартного -SettingsPath укажите тот же путь при Restore. Копия текущего файла сохраняется как settings.before-restore.

Защита Firewall/WFP откатывается отдельно штатным Restore.cmd комплекта. Не используйте глобальный сброс Firewall. Новый файл пользовательских настроек не входит в административный snapshot защиты: используйте оба механизма, если нужен полный откат.

## Дочерние процессы

Setup и обновление добавляют CodeRoot — отдельный каталог claude-code в пользовательском кэше Desktop. Sync ставит такие же ограничения на уже существующие EXE из этого каталога, даже если они находятся вне WindowsApps. Переходы через junction/symlink запрещены. Это дополнительная защита известных файлов, а не гарантия перехвата первого соединения нового EXE до следующей синхронизации.

Обновленный проверяемый запуск передает HTTP_PROXY/HTTPS_PROXY/ALL_PROXY/NO_PROXY окружению Desktop; обычные дочерние процессы наследуют его. Это помогает proxy-aware утилитам. WFP-ограничение ClaudeProxyOnly сохраняется для процессов с соответствующим тегом; перехват для встроенного Code подтвержден реальным журналом.

Это не универсальный прозрачный прокси для всех потомков: программа может игнорировать env, переопределить прокси, запуститься через службу, WSL/SSH или выйти из контекста пакета. Периодическое добавление правил по PID не устраняет гонку первого соединения. Для гарантии всех произвольных потомков нужен отдельно проверенный механизм изоляции/перехвата с учетом дерева процессов и DNS. В этой правке новый драйвер или широкая политика App Control не устанавливаются. Для утилиты без поддержки прокси корректным результатом ограничения может быть отказ подключения.

Документация: https://code.claude.com/docs/en/network-config

## Исправление ожидания Verify (r3)

Verify больше не открывает транзакцию записи WFP перед запросом профилей Firewall через CIM. Этот порядок мог взаимно блокировать диагностический процесс и системного провайдера. Manage-Happ запускает Verify отдельным работником с лимитом 45 секунд; при превышении времени останавливается только этот работник, разрешение на запуск Claude не выдается.

Если уже установлен старый вариант и административная проверка зависла, отмените/закройте именно ее окно. При закрытом Claude запустите из обычного PowerShell `Repair-VerifyWait.ps1`: он запросит UAC, сохранит копии Common.ps1, Sync-Guard.ps1 и Manage-Happ.ps1 в защищенном RepairBackups, установит совместимые диагностические скрипты и выполнит ограниченную по времени проверку. Правила WFP/Firewall он не меняет. Затем отдельно выполните установленный `Launch-Checked.ps1 -CheckOnly -NoPause`.

На существующей машине 2026-10-30 подтверждены STATIC VERIFY PASS, неизменность 137 ключей фильтров, защищенные HTTP CONNECT/SOCKS-тесты с отрицательными проверками обхода и CHECK ONLY PASS. Агент Claude не запускал. После этого владелец сам проверил Code и сообщил об успешной работе. Новый тест реального отключения Happ с самим клиентом после этих изменений не объявляется выполненным.
