# Как работает защита

## Два клиента, один локальный прокси

Desktop — Electron-приложение с аргументом `--proxy-server=socks5://127.0.0.1:PORT`, отключенным QUIC и явным запретом обхода loopback. Code — отдельный скачанный EXE вне WindowsApps. Он получает HTTP-прокси в пользовательском `settings.json`; SOCKS-аргумент Desktop его не заменяет. Настраиваются HTTP_PROXY, HTTPS_PROXY, ALL_PROXY и пустой NO_PROXY. HTTPS_PROXY имеет схему `http://`: TLS целевого сайта идет внутри HTTP CONNECT локального прокси.

Обычные дочерние процессы наследуют proxy-окружение проверяемого запуска. Утилита может игнорировать его; WSL, SSH, VM и внешние службы требуют отдельного исследования. Это не прозрачное перенаправление всех сокетов по дереву PID.

## Уровни ограничений

1. WFP-фильтры для обнаруженных EXE Desktop и кэша Code разрешают только TCP к `127.0.0.1:ProxyPort`: блокируют другой IPv4, порт, UDP и IPv6.
2. При включенном UseLegacyTag используются существующие процессы с тегом ClaudeProxyOnly. Сам тег создается внешней AppID-политикой; установщик v3.3 не устанавливает ее. При новой установке без такой политики теги не дают дополнительного охвата.
3. Для внутреннего `xray.exe` Happ разрешен один адрес/порт сервера. Порт локального прокси может занимать только указанное ядро. Сохраняются собственные правила Firewall, включая блокировку указанных виртуальных интерфейсов.
4. Точный IPv4-маршрут сервера задается через физический адаптер и его шлюз. Виртуальный вместо физического не принимается.

Нативные фильтры WFP могут отсутствовать в обычном списке правил `Get-NetFirewallRule`. Для выяснения причины отказа нужно событие Security 5157/5152 и FilterRTID/FilterOrigin, сопоставленные со снимком WFP.

## Проверяемый запуск

Родительский скрипт работает обычным пользователем. Он проверяет SID, отсутствие открытого клиента, пользовательские настройки Code и доступность HTTP-прокси. Через UAC запускается Preflight: Diagnose, при ошибке один Fix, затем повторный Diagnose. Установленный код проверки не выбирает другой сервер и не ослабляет ограничения для подключения.

Административный результат записывается в защищенный LaunchTickets с новым ID. Родитель проверяет ID, пользователя, SHA256 конфигурации, актуальность EXE и давность не более 30 секунд. При OK обычный запуск открывает Desktop; CheckOnly завершается до этого шага. Запуск ярлыка от администратора отклоняется.

Полная диагностика проверяет точные фильтры, текущие EXE, маршрут, задачу, владельца порта, адрес сервера и внешние соединения Happ. Static Verify читает WFP без транзакции записи; запускается отдельным работником с лимитом 45 секунд.

Защищенный curl получает те же четыре ограничения для EXE. Несколько HTTPS-сервисов должны показать один IP и выбранную страну. Проверяются SOCKS, HTTP CONNECT, запрет прямого подключения, другого локального порта и обхода во время искусственного отказа прокси только для тестового EXE. После испытания удаляются его тестовые фильтры. Happ при этом физически не выключается.

## Сервер и DNS

В Hostname-режиме два независимых HTTPS DNS-запроса привязаны к физическому интерфейсу. Требуется один согласованный публичный IPv4. Fix может обновить закрепленный адрес того же домена; расхождение не разрешает выбор случайного сервера.

В PinnedIPv4-режиме используется явный публичный UpstreamAddress. DNS адреса сервера пропускается; DNSVerified=false в отчете нормально при EndpointVerified=true. Смена адреса выполняется пользователем через Reconfigure и резервную копию.

Проверка страны относится к внешнему выходу, а не к самому адресу сервера. Провайдер может менять выходной IP. Комплект не предоставляет сервер и не делает динамический IP статическим.

## Обновления и резервные копии

SYSTEM-задача `\ClaudeHappOnly\Sync` при загрузке и каждую минуту добавляет ограничения известных EXE и поддерживает ярлык. Она не запускает Claude. Сохраняются ограничения старых версий. CodeRoot охватывает существующие EXE выделенного кэша claude-code; junction/symlink не обходятся.

До Install/Fix создается административный снимок собственных файлов, фильтров, правил, маршрутов, задачи и ярлыка. До Restore создается предохранительный снимок. Полный `.wfw` сохраняется как справочный файл; обычный Restore не импортирует его глобально и не сбрасывает чужие правила.

Настройки Code изменяет обычный пользователь. У них отдельные копии и hash-checked Restore: более новые изменения не затираются. Для полного отката могут понадобиться оба механизма. Снимки привязаны к компьютеру и не служат переносом конфигурации на другой ПК.

## Границы

Проверяемый ярлык не перехватывает все способы создания процесса Windows. Неизвестный новый EXE до обнаружения задачей не получает автоматически path-фильтр. Наличие тега у одного Code-процесса не доказывает теги у всех потомков. Клиент, программа без поддержки прокси, WSL/VM или служба могут вести себя иначе. Испытанные блокировки и пользовательский успешный запрос — доказательства конкретных механизмов, а не гарантия всех возможных сценариев.

Рабочие файлы и системные снимки защищены ACL Administrators/SYSTEM; обычному пользователю оставлено чтение. Личные данные и отчеты не публикуйте вместе с исходным кодом. Установка не меняет Chrome proxy extensions, подписку Happ, MTU или глобальный прокси Windows.
