# Claude через Happ: универсальный комплект Windows x64, v3

Комплект устанавливает защиту и ярлык с обязательной проверкой туннеля. Настраиваются пользователь, пути, физический адаптер, порты, имя сервера и страна выхода. Требуются Windows x64, Windows PowerShell 5.1, системный curl, Windows Firewall/WFP, уже установленные Happ с ядром Xray и Claude Desktop. В ZIP нет Happ, Claude, подписки или её ключей. Другие ОС, иное ядро Happ и транспорт удалённого сервера UDP не поддерживаются. Новых драйверов и WDAC-политик установщик не устанавливает.

## Установка на другом компьютере

1. Распакуйте ZIP целиком. Установите Happ и Claude. Настройте сервер Happ и SOCKS на 127.0.0.1. TUN выключите; общий системный прокси не требуется.
2. Запустите **Install.cmd** обычным двойным щелчком. Мастер спросит домен выбранного сервера (не URL подписки), имя физического Ethernet/Wi-Fi адаптера, локальный SOCKS-порт, страну, путь к внутреннему xray.exe и TCP-порт удалённого сервера.
3. Для Microsoft Store оставьте семейство пакета по умолчанию. Для отдельной установки укажите каталог Claude и полный путь к claude.exe. Защищаются EXE внутри указанного каталога, а не произвольные внешние дочерние программы.
4. При наличии FlClashX укажите точное имя его виртуального интерфейса в списке явно блокируемых интерфейсов. Физический интерфейс должен иметь один IPv4-адрес и один IPv4-шлюз; виртуальный вместо физического не принимается.
5. Подтвердите UAC. Установщик сохранит ограничения, создаст ярлык и проверит сеть на curl. **Claude при установке и диагностике не запускается.** Если после установки требуется переподключение Happ, переподключите тот же сервер и выполните Diagnose.cmd.

Можно подготовить собственный JSON по `configuration.example.json` и выполнить `Setup.ps1 -ConfigurationFile ПОЛНЫЙ_ПУТЬ`. LaunchUserSid — SID обычного пользователя, нажимающего ярлык; ShortcutPath — путь его ярлыка. Интерактивный мастер заполняет их автоматически. Персональный JSON с другой машины не используйте.

Универсальность означает настройку перечисленных параметров. Несколько A-адресов сервера, расхождение DNS, IPv6-only сервер, UDP-транспорт и нестандартная структура пакета вызывают отказ вместо ослабления защиты. На другой физической машине комплект пока не испытывался. На уже защищённой машине смена порта или пути ядра требует отдельной миграции старых фильтров; они автоматически не снимаются.

## Проверяемый запуск

Ярлык **Claude - Happ Only** указывает на защищённый `Launch-Checked.ps1`, а не непосредственно на claude.exe:

1. Родитель работает с обычным пользовательским токеном. Запуск ярлыка «от имени администратора» отклоняется.
2. Через UAC выполняется отдельная административная проверка: WFP/Firewall, актуальные EXE, маршрут, DNS, задача защиты, владелец SOCKS-порта, внешние соединения Xray и защищённый опыт curl.
3. При первом FAIL выполняется **один Fix**, затем **ещё один Diagnose**. Автоматического выбора другого сервера или бесконечных повторов нет.
4. Результат с новым случайным ID сохраняется в каталоге с записью только Administrators/SYSTEM. Родитель проверяет код завершения, свежесть (30 секунд), ID, пользователя, конфигурацию и актуальный путь EXE.
5. При полном OK Claude запускается обычным пользователем с явным SOCKS, отключённым QUIC и без обхода loopback. Любая ошибка, отмена UAC или несовпадение отменяет запуск и показывает отчёт.

Нажатие пользователем этого ярлыка означает запрос реального запуска Claude после проверки. Для испытания без запуска есть **Launch-Checked.ps1 -CheckOnly**: тот же путь до последнего шага, затем остановка перед Start-Process Claude. Установщик ярлык не исполняет.

Обязательная предварительная проверка относится **к этому ярлыку**. Windows по-прежнему может создавать процесс Claude через «Пуск», протокол приложения или прямой вызов EXE. Эти способы не выполняют curl-проверку. Постоянные сетевые ограничения защищённых EXE действуют независимо от способа запуска. Для обычной работы используйте созданный ярлык. Контроль всех точек создания процесса потребовал бы отдельного механизма контроля запуска.

## Что проверяется

Фильтры должны точно соответствовать текущим EXE и настройкам. Cloudflare и Google по HTTPS должны дать один одинаковый публичный IPv4 сервера; диагностические DNS-соединения привязаны к выбранному физическому интерфейсу. Точный маршрут и существующие внешние TCP-соединения ядра должны соответствовать закреплённому серверу, порту и физическому интерфейсу.

Копия системного curl получает те же четыре постоянных WFP-ограничения для EXE: только TCP к заданному 127.0.0.1:SOCKS-порту. Три HTTPS-сервиса должны показать один IP, два — выбранную страну. Прямое подключение, другой локальный порт и прямой обход при искусственной недоступности прокси должны получить отказ WFP. После снятия искусственного отказа IP должен совпасть. Удаляются только тестовые фильтры.

Это подтверждение механизма и текущего состояния. Оно не проверяет реальное поведение Claude/Cowork, AppID-присвоение, внешние программы и VM; не гарантирует неизменность IP провайдера навсегда. При потере Happ после запуска постоянные ограничения продолжают блокировать альтернативные подключения. Программа может пытаться переподключаться; запрещённые попытки блокируются.

## Диагностика, исправление, отчёты

- **Diagnose.cmd** — проверка с curl без запуска Claude. Временные тестовые фильтры создаются и удаляются; постоянные настройки не исправляются.
- **Fix.cmd** — восстановление файлов, ограничений, собственной задачи и маршрута; обновление адреса того же сервера после согласованного DNS; сетевой тест. Ограничения ради подключения не отключаются.
- **Install.cmd** — мастер новой установки. Для обычного восстановления установленной конфигурации используйте Fix.

Рабочие файлы: `%ProgramData%\ClaudeHappOnly`, запись только Administrators/SYSTEM. Задача `\ClaudeHappOnly\Sync` при загрузке и каждую минуту добавляет защиту EXE новых версий и поддерживает проверяемый ярлык. Она не запускает Claude и не выдаёт допуск к запуску.

Отчёты: `%ProgramData%\ClaudeHappReports`. Краткий итог — SUMMARY.txt; полные данные — result.json, experiment.json, журналы и task-check.json. Подготовка запуска сохраняется в preflight-ID; результат допуска — в ClaudeHappOnly\LaunchTickets\ID.json. Старый отчёт не разрешает новый запуск.

Типовые действия: HAPP_LISTENER — подключить прежний сервер в Happ; PIN_CHANGED — Fix; DNS_UNVERIFIED — проверить физическое соединение и повторить; GUARD/FIREWALL_RULE/TASK — Fix; NETWORK_TEST_FAILED — переподключить тот же сервер и повторить, затем проверить провайдера. Чужие конфликтующие маршруты не удаляются автоматически. Другой владелец порта вызывает отказ запуска.

Установщик включает профили Firewall и заменяет только собственные именованные правила Happ. Не меняет подписку, настройки FlClashX, MTU, глобальный прокси или фрагментацию. Резервные копии прежних файлов находятся в отчёте. Подписка и её секреты не экспортируются. SHA256 проверяет случайную порчу комплекта, но не заменяет цифровую подпись и доверенный источник ZIP.

## Резервные копии v3.1

Перед Install и Fix автоматически создаётся полная копия состояния нашей защиты в %ProgramData%\ClaudeHappBackups. Для отката используйте Restore.cmd, для списка — Restore.cmd -List, для выбранной копии — Restore.cmd -BackupId ID. Перед откатом создаётся ещё одна копия; после него запускается диагностика без Claude. Подробности, состав копии и ограничения — в RESTORE-ru.md.
