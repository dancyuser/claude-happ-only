Claude TUN Only adds an installer that discovers Claude executables and the active TUN without requesting the VPN server IP. Persistent WFP rules block connections through other interfaces and block IPv6 for the selected executables.

The checked Claude Desktop launcher disables the inherited system proxy for that process. Diagnostic DNS is resolved before starting the protected curl process, and interface-only profiles accept legitimate split routing. The WFP library is compiled before elevation and checked by hash when copied into the protected installation.

Validation includes Windows PowerShell 5.1 static checks, live TCP/UDP and actual TUN-loss tests on separate probes, and an isolated Chromium regression test for system-proxy failure versus direct TUN access. Claude itself was not relaunched after the final proxy correction. Device reboot, a clean device and version-independent coverage after a Claude update remain outside the validated scope. Rerun the installer after executable paths change.

Security software can block software that changes filtering policy. Review any detection; this package does not disable antivirus or add exclusions. See CLAUDE-TUN-ru.md for setup, boundaries and recovery.
