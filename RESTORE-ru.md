# Резервные копии и откат

Перед каждым **Install** и **Fix**, в том числе автоматическим Fix при подготовке запуска, создаётся отдельная резервная копия. Если копирование или проверка нужных данных не удалась, изменения не продолжаются. Задача Sync временно приостанавливается для согласованного снимка; её исходный XML сохраняется до приостановки.

Копии находятся в **%ProgramData%\ClaudeHappBackups\ID**. ID выглядит как `20260101-120000-000-01234567`. Они остаются после перезагрузки и автоматически не перезаписываются/не удаляются. Каталог и файлы доступны на запись только Administrators/SYSTEM. Результат Install/Fix содержит Backup и BackupId, в окне печатается строка BACKUP.

## Что сохраняется

Это административный снимок защиты. Пользовательский settings.json Code сохраняется отдельно при Apply/Setup/Update; для него используйте Configure-CodeProxy.ps1 -Mode Restore -BackupId ID в обычном PowerShell при закрытом клиенте. При конфликте с более новыми правками автоматический откат пользовательского файла отклоняется. Для полного отката могут понадобиться оба механизма; [CODE-PROXY-ru.md](CODE-PROXY-ru.md).

- Исходники и конфигурация нашей защиты, state.json, параметры проверяемого запуска. Для каждого файла фиксируется, существовал ли он до изменения.
- Пять собственных правил Happ Firewall с адресами, портами, программой, интерфейсами и прочими используемыми параметрами; дополнительный исходный XML для разбора.
- Полный экспорт Firewall `firewall-full.wfw` для аварийного разбора и исходные состояния включения трёх профилей. Обычный Restore **не импортирует весь .wfw** и не сбрасывает правила остальных приложений.
- Точные постоянные фильтры WFP нашего подслоя: ключи, слои, условия, двоичные AppID/SDDL-данные и веса.
- Снимок IPv4-маршрутов /32 и отдельный журнал намерений создания маршрутов. При откате удаляются только записанные в журнале точные новые маршруты, отсутствовавшие до изменения, с совпадающими интерфейсом, шлюзом и метрикой. Маршрут прежнего сервера восстанавливается из снимка; чужой конфликтующий маршрут вызывает отказ автоматического перезаписывания.
- XML нашей задачи планировщика и исходные ярлыки.

Снимок не содержит подписку Happ, её ключи или содержимое Claude. Полный экспорт Firewall может содержать пути и сведения о правилах других программ — это локальный аварийный материал, он не отправляется в сеть.

## Как восстановить

1. Закройте клиент Claude и Code-сессии самостоятельно. Проверенная зарегистрированная CoworkVMService может оставаться в фоне. Restore не запускает и не завершает их.
2. Запустите **Restore.cmd** и подтвердите UAC. Он покажет копии с датой и причиной создания. Введите нужный BackupId. Пустой ответ отменяет операцию.
3. Либо используйте явные команды:

```powershell
.\Restore.cmd -List
.\Restore.cmd -BackupId 20260101-120000-000-01234567
```

Сам ID в примере нужно заменить своим. Также можно вызвать `Restore-Entry.ps1 -BackupId ID`. В установленной папке тот же вход — `%ProgramData%\ClaudeHappOnly\Restore-Entry.ps1`; архив нужно сохранять как независимое средство восстановления, если установленные файлы повредятся.

Перед откатом проверяются контрольные суммы, права доступа, завершённость снимка и принадлежность этой установке Windows. Копию с другого компьютера использовать нельзя. Автоматическое восстановление не запускает код из произвольного указанного пути: выбирается только ID в защищённом каталоге копий.

Перед изменениями Restore создаёт **ещё одну копию текущего состояния**, причина Before-Restore-ID. На время отката исходящие подключения EXE Claude закрываются дополнительными противоречащими фильтрами. Затем восстанавливаются свои правила, записанные маршруты, файлы, ярлык, профили и задача. Фильтры WFP восстанавливаются транзакцией; если после снимка обновился Claude, обнаруженные текущие EXE также получают прежние ограничения. Поэтому state.json может получить актуальный список EXE и отметку RestoredFrom, а не побайтовое старое содержимое.

После отката запускается полная диагностика с тестовым curl — **Claude не запускается**. Сообщение RESTORED и NetworkOK=True означает, что настройки возвращены и текущая проверка туннеля прошла. Если сервер или DNS успел измениться со времени снимка, настройки могут быть восстановлены, но сеть останется неработоспособной: смотрите отчёт, переподключите прежний сервер или выполните Fix.

При незавершённом Restore остаётся maintenance.txt, и проверяемый запуск Claude отклоняется. Во время частичного отката могут остаться дополнительные блокирующие фильтры: это отказ в доступе, а не разрешение обхода. Успешный повторный Restore либо успешный Fix убирает временную блокировку. Не удаляйте фильтры или maintenance.txt вручную, чтобы обойти ошибку.

Restore не является деинсталлятором: снимок **до первоначальной установки**, где ещё не было защиты, не используется для автоматического снятия последней защиты. Копия сохраняется для разбора, но для обычного отката нужен HadGuard=True. Снимок незавершённого обслуживания (Maintenance=True) тоже не используется как целевое состояние: выбирайте более ранний. Восстановление старой версии исходников может вернуть поведение этой версии; сохраните актуальный архив v3.1 для дальнейшего обновления.

Все отчёты находятся в **%ProgramData%\ClaudeHappReports\restore-ДАТА-ВРЕМЯ**. В result.json записаны целевая копия, предохранительная копия, состояние отката и результат диагностики. Данные файлов проверяются SHA256; журнал намерений маршрутов дописывается в ходе исправления и защищён административными правами доступа.
