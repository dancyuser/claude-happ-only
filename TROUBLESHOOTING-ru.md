# Диагностика и типовые исправления

Сначала различайте обычный чат Desktop и встроенный Code. У них разные процессы и настройки прокси. Не отключайте Firewall и не добавляйте общее разрешение claude.exe/node.exe: это может убрать ошибку ценой обхода Happ.

## Где искать результат

Запустите `Diagnose.cmd` при самостоятельно закрытом Claude. Итоговые файлы находятся в `%ProgramData%\ClaudeHappReports\ДАТА-ВРЕМЯ`:

- `SUMMARY.txt` — краткая причина;
- `result.json` — состояние, режим адреса и результаты этапов;
- `experiment.json`, `probe-checks.json` — положительные и отрицательные curl-тесты;
- `verify.log`, `verify-error.log` — ограниченная 45 секундами статическая проверка;
- `run.log` — ход диагностики.

У запуска через ярлык отчеты находятся в `preflight-ID`, допуск — в `%ProgramData%\ClaudeHappOnly\LaunchTickets\ID.json`. Старый OK не разрешает новый запуск. Системная синхронизация пишет `%ProgramData%\ClaudeHappOnly\sync-latest.log`.

| Сообщение / симптом | Проверить и исправить |
|---|---|
| Desktop работает, Code выдает ECONNREFUSED | Проверить HTTP CONNECT и пользовательский settings.json. SOCKS-аргумент Desktop не настраивает Code. При закрытом Claude выполнить Configure-CodeProxy -Mode Apply, затем CheckOnly и новую Code-сессию |
| ERR_NETWORK_ACCESS_DENIED | Посмотреть фактический процесс и блокирующий WFP-фильтр. Если процесс пытается выйти напрямую, настроить его прокси; фильтр обхода не удалять. При старом открытом Desktop Reload не добавит SOCKS-аргумент |
| HAPP_LISTENER | В Happ подключить нужный сервер, проверить 127.0.0.1 и локальный порт. Не путать локальный порт с портом удаленного сервера |
| WRONG_PROXY_OWNER | Порт занят другим EXE. Полная диагностика показывает владельца. Использовать нужный экземпляр Happ или выбрать свободный порт при новой установке |
| HTTP-тест не проходит, SOCKS работает | Code нужен HTTP CONNECT. Проверить тип inbound в Happ на том же порту. Не назначать HTTPS_PROXY=socks5://… |
| PIN_CHANGED | Если домен и выбранный узел верны, Fix обновит его IP после согласованного DNS. Если выбран другой сервер — Reconfigure с его доменом/IP |
| DNS_UNVERIFIED | Проверить физическое подключение, доступность HTTPS DNS, один A-адрес и совпадение ответов. Старый pin не заменяется случайным. PinnedIPv4 допустим только с явно выбранным проверенным IP |
| DNSVerified=false в PinnedIPv4 | Нормально, если EndpointVerified=true. В этом режиме DNS сервера не выполняется |
| NETWORK_TEST_FAILED | Посмотреть конкретный curl, код, IP и страну. Переподключить тот же сервер Happ. При одинаковом отказе HTTPS возможна проблема сервера/провайдера; увеличение разрешений это не диагностирует |
| Выходная страна не совпала | Проверить реально подключенный узел Happ и маршрутизацию. ExpectedCountry менять только при намеренной смене страны |
| GUARD / FIREWALL_RULE / TASK | Fix восстанавливает собственные ограничения и задачу с резервной копией. Проверить sync-latest.log и доступность актуального пакета/CodeRoot |
| Conflicting exact route | Проверить route print и Get-NetRoute для серверного /32. Старый маршрут может относиться к прежнему физическому интерфейсу или другому ПО. Чужой маршрут скрипт не удаляет. Не сбрасывать всю таблицу маршрутов |
| Existing guard uses another port/core path | Автоматическая смена уже закрепленных портов/пути запрещена. Вернуть прежние значения либо подготовить отдельную миграцию. На новой машине выбрать нужные значения в Setup |
| Reparse point / abnormal inventory | Проверить CodeRoot и путь установки. Комплект не следует по junction/symlink и не расширяет защиту на произвольный каталог пользователя |
| Wrong configured user / different user | Запускать мастер обычным целевым пользователем. Не переносить ProgramData/config.json с SID другого ПК. Не запускать весь Setup от администратора |
| Отказано в доступе до UAC | Обновить комплект: старый updater запрашивал Get-AppxPackage -AllUsers до повышения. Новый Update-CodeSupport -ValidateOnly проверяет начальные этапы без UAC и изменений. При другом отказе сохранить напечатанные шаг/ErrorId/стек |
| UAC отменен | Установка/проверка не закончена, Claude не запускается. Повторить нужную команду при готовности подтвердить системный запрос |
| Организационная политика запрещает скрипт/Add-Type | Нужна разрешенная администратором среда. Комплект не отключает App Control/EDR или корпоративные политики |

## Проверить Code отдельно

Из папки распакованного комплекта, в обычном PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Configure-CodeProxy.ps1 -Mode Diagnose
```

Нужны OverallOK=True, SettingsOK=True, Transport.OK=True. Если HTTP работает, а SettingsOK=False, полностью закройте Claude и выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Configure-CodeProxy.ps1 -Mode Apply
```

Для своего порта/страны передайте `-ProxyPort PORT -ExpectedCountry XX` из установленной конфигурации. Apply создает отдельную резервную копию и не запускает Claude. Управляемые настройки организации и настройки проекта могут иметь приоритет; локальный Diagnose не доказывает их отсутствие. После успешных проверок пользователь сам создает новую Code-сессию и проверяет `/status` и запрос.

## Если административная проверка долго стоит

Новая статическая проверка имеет лимит 45 секунд, каждый curl — свой лимит. Полная последовательность может занять несколько минут при недоступных внешних сервисах, но не должна бесконечно стоять на одном Static Verify.

В старом варианте Verify открывал WFP-транзакцию перед чтением Firewall через CIM, что могло вызвать взаимную блокировку. Если такое окно уже зависло, отмените его Ctrl+C или закройте именно диагностическое окно. Затем при закрытом Claude из нового комплекта выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Repair-VerifyWait.ps1
```

Он запросит UAC, сохранит диагностические скрипты и Common.ps1, установит совместимое исправление и проверит Verify с лимитом времени. Правила не меняются. Затем — установленный Launch-Checked с `-CheckOnly -NoPause`. Не запускайте несколько Fix одновременно.

## Найти конкретный блокирующий фильтр

Для воспроизводимой проблемы нужен короткий аудит WFP 5157/5152 с точным временем ошибки, Application, PID, адресами/портами, InterfaceIndex, FilterRTID и FilterOrigin. Снимите `netsh wfp show filters file=... verbose=on` в той же загрузке Windows: runtime ID фильтра может меняться. Сопоставляйте с именем фильтра и процессом, а не только с traceroute.

Обычный Get-NetFirewallRule не показывает все нативные WFP-фильтры. Метка Claude-Happ-Only с v4-address/port/protocol/v6 означает сработавший собственный запрет. Запись для xray.exe относится к участку Happ → сервер; запись для claude-code → внешнего адреса означает, что эта попытка не направлена в локальный прокси. Ошибка ECONNREFUSED сама по себе не доказывает Firewall.

Временное включение аудита требует администратора; сохраните прежние значения и верните их после короткого захвата. Отсутствие событий не доказывает исправность — отказ мог возникнуть до сокета, в TLS/HTTP/авторизации или в другой среде. Не публикуйте полные логи с токенами, SID и пользовательскими путями.

## Откат

Не используйте глобальный сброс Firewall. Системный Restore и откат пользовательского settings.json независимы: [RESTORE-ru.md](RESTORE-ru.md), [CODE-PROXY-ru.md](CODE-PROXY-ru.md). Restore не затирает более новые правки пользовательских настроек; при конфликте понадобится ручное объединение с сохраненной копией.
