# Универсальная настройка Windows 11 x64

Универсальный модуль работает с выбранными EXE и явно выбранным сетевым интерфейсом. Он не требует названий Claude, Happ, SnowVPN, FlClashX или конкретного производителя адаптера. Прежняя настройка Claude/Happ остается отдельным готовым вариантом. Установка универсального профиля сама не запускает защищаемые приложения и не подключает VPN.

Это предварительный выпуск. Проверены оба режима на одном Windows 11 с тестовой копией curl и реальным WFP. Установка на чистом ПК, реальный разрыв VPN, перезагрузка, UDP и IPv6 требуют дополнительных живых испытаний. Android, iOS, Linux, ARM64 и отсутствие WFP этим пакетом не поддерживаются.

## Выбор режима

| Режим | Разрешенный путь | Что требуется |
| --- | --- | --- |
| TUN + Proxy (`TunProxy`) | Выбранные EXE → TCP 127.0.0.1:порт → выбранное сетевое ядро прокси → один сервер через выбранный нижележащий интерфейс | Локальный HTTP CONNECT или SOCKS5-прокси; путь к процессу-владельцу порта; IP/порт/протокол сервера; интерфейс транспорта |
| TUN (`TunOnly`, `InterfaceAndCore`) | Выбранные EXE → выбранный TUN; сетевое ядро VPN → только указанный сервер | Виртуальный TUN; отдельный идентифицируемый EXE сетевого ядра; IP/порт/протокол сервера VPN |
| TUN (`TunOnly`, `InterfaceOnly`) | Выбранные EXE → только выбранный TUN | Виртуальный TUN; явное принятие ограничения этого варианта |

`InterfaceOnly` — собственная блокировка обхода выбранного интерфейса. Если он исчезает и Windows выбирает Ethernet/Wi-Fi, постоянные WFP-фильтры не разрешают такой путь выбранным EXE. Для этого не требуется ждать опроса наблюдателя.

Но VPN-клиент может оставить TUN активным и пересылать трафик напрямую по своим правилам DIRECT. `InterfaceOnly` этого не предотвращает. Поэтому мастер по умолчанию предлагает `InterfaceAndCore`: дополнительно сетевому ядру VPN разрешен только указанный сервер. Эта настройка влияет на весь трафик, который обрабатывает данный EXE ядра. Ошибка в его адресе/порте может отключить VPN и другие использующие его программы. Заранее подготовьте правильные параметры и резервный способ скачать инструкции.

Для VPN, реализованных общим системным сервисом или драйвером без отдельного EXE, строгий вариант нельзя автоматически считать применимым. Не выбирайте весь svchost.exe или System как замену неизвестному ядру. Используйте документированный kill switch провайдера либо отдельно проверяйте другую схему изоляции. Поддержка произвольного имени VPN не означает доказанную совместимость с каждой внутренней архитектурой.

## Установка

1. Установите и настройте свои VPN и прокси. Подключите нужный сервер. Мастер не меняет подписки и правила провайдера.
2. Распакуйте весь комплект. Откройте `Install.cmd`, выберите **1 — Universal**. Либо сразу откройте `Install-Universal.cmd`. Используйте обычную учетную запись, не административный PowerShell.
3. Укажите название профиля и режим. Добавьте точные пути ко всем EXE, которым требуется защита. Папки и маски не принимаются. Настройка охватывает все запуски этих EXE, в том числе вне созданного профиля.
4. Выберите адаптер из списка по номеру. Название выводится для удобства, сохраняется **InterfaceGuid**, а WFP получает соответствующий **NET_LUID**. Смена имени/ifIndex не является выбором другого адаптера. При отсутствии GUID программа не выбирает похожее устройство.
5. Для Proxy укажите локальный порт, протокол `http` или `socks5h`, EXE владельца порта, IP/порт/протокол вышестоящего сервера и интерфейс транспорта. Это должен быть сетевой процесс, а не только окно VPN-клиента. Вводится один закрепленный IP, не домен. Поддерживаются TCP или UDP к одному серверному порту.
6. Для TUN выберите строгий вариант с ядром VPN либо явно ограниченный `InterfaceOnly`. IPv6 выбранным клиентам по умолчанию блокируется. Разрешать его через TUN следует только после проверки маршрутизации IPv6.
7. Укажите ожидаемую страну выхода либо оставьте `-`, чтобы принимать любую. Закройте выбранные защищаемые приложения самостоятельно. Подтвердите UAC.
8. Установщик сохраняет резервную копию, ставит постоянные WFP-ограничения атомарной транзакцией и проверяет сеть своей копией curl. Успех — `TESTED` и `Ready=true` в отчете. После успеха создается ярлык `Network Guard - <ProfileId>` на рабочем столе для проверки и пользовательского запуска первого EXE. Одна установка может завершиться с ограничениями, но без успешной сети: это не разрешение запуска.

Пользовательский файл параметров: `%LOCALAPPDATA%\UniversalNetworkGuard\Profiles\<ProfileId>.json`. Административные файлы: `%ProgramData%\UniversalNetworkGuard\Profiles\<ProfileId>`. Отчеты: `%ProgramData%\UniversalNetworkGuard\Reports\<RequestId>\result.json`.

Не копируйте готовую конфигурацию с чужого ПК без адаптации: пути, GUID и пользователь относятся к конкретному устройству. На другом ПК пройдите мастер заново. В комплекте есть шаблоны `universal-tun.example.json` и `universal-proxy.example.json`; адреса и пути в них являются примерами.

## Запуск приложения

Сохраненные ограничения действуют для выбранных EXE постоянно; запуск вне ярлыка не снимает их. Для свежей проверки перед пользовательским запуском:

```powershell
# Выполняйте из распакованного комплекта. Подставьте ID своего профиля.
.\Start-Universal.ps1 -ProfileId '11111111-1111-1111-1111-111111111111'
```

Будет проверена сеть через защищенную диагностическую копию curl и свежий отчет, после чего запустится первый EXE профиля. Другой EXE из того же профиля можно выбрать параметром `-Executable`. `-ApplicationArguments` принимает массив аргументов программы. Агент этот запуск для Claude не выполняет.

Для Proxy дочернему процессу задаются HTTP_PROXY/HTTPS_PROXY/ALL_PROXY и пустой NO_PROXY. Поддержка этих переменных зависит от приложения. Программу, которая их игнорирует, настройте на прокси штатным способом или передайте ее документированный аргумент. Например, Electron/Chromium может требовать собственный `--proxy-server`. Модуль не угадывает аргументы неизвестных приложений, не устанавливает TLS-сертификаты и не реализует прозрачное перенаправление всего Winsock. Приложение без поддержки прокси получит отказ в сети.

Для TUN переменные прокси удаляются из окружения запускаемого процесса. Собственные настройки прокси внутри приложения нужно проверить отдельно. В режиме TUN доступ к посторонним локальным прокси и другим интерфейсам тоже блокируется; приложению может потребоваться адаптация локального IPC.

## Изменение параметров и диагностика

```powershell
# Адаптеры и установленные профили — без UAC и изменений.
.\Universal-Guard.ps1 -Mode List

# Просмотр кандидата конфигурации — без установки.
.\Universal-Guard.ps1 -Mode Install -ConfigurationFile 'C:\path\profile.json' -Preview

# Повторная установка того же ProfileId с новыми параметрами и резервной копией.
.\Universal-Guard.ps1 -Mode Install -ConfigurationFile 'C:\path\profile.json'

# Проверка постоянных фильтров, без проверки внешнего IP.
.\Universal-Guard.ps1 -Mode Verify -ProfileId '11111111-1111-1111-1111-111111111111'

# Проверка фильтров + положительные и отрицательные сетевые тесты.
.\Universal-Guard.ps1 -Mode Test -ProfileId '11111111-1111-1111-1111-111111111111'
```

Чтобы сменить VPN/сервер/адаптер, сначала закройте выбранные приложения. Измените пользовательский JSON с сохранением ProfileId, затем выполните Install. IP сервера самопроизвольно не расширяется. Удаленный и заново созданный виртуальный адаптер может получить другой GUID; выберите его явно. Не считайте его прежним по совпадению имени. При обычном разрыве соединения постоянные ограничения не снимаются.

Путь нового EXE после обновления программы нужно добавить в Programs и повторить Install. При переезде приложения на другой путь прежний фильтр не защищает новый EXE автоматически. Отдельная установка поверх EXE уже защищенного профиля запрещается: обновите этот профиль. Для текущего Claude/Happ требуется осознанная миграция его старых ограничений; универсальный мастер не удаляет их автоматически.

## Резервные копии и Restore

При Install/Restore создается собственная резервная копия в каталоге профиля `Backups\<BackupId>`: конфигурация, план и ключи своих WFP-фильтров, рабочие скрипты и диагностическая программа с SHA256. Машина и ProfileId проверяются. Полный firewall не импортируется, чужие правила и прежний Claude/Happ не сбрасываются.

```powershell
.\Universal-Guard.ps1 -Mode Restore `
    -ProfileId '11111111-1111-1111-1111-111111111111' `
    -BackupId '22222222-2222-2222-2222-222222222222'
```

Восстановление требует закрытых выбранных клиентов. Если копия относится к состоянию до первой установки, Restore снимает ограничения этого универсального профиля. Если до обновления — возвращает предыдущий план. После Restore выполните Test перед запуском. Автоматического запуска приложений нет. Ярлык после полного удаления профиля можно удалить вручную; без установленной конфигурации он откажет в запуске.

При ошибке внутри установки WFP-транзакция откатывается и программа пытается восстановить файлы. Если сеть не прошла тест после успешной установки фильтров, они сохраняются: это ошибка готовности, а не причина разрешить прямой выход. `maintenance.json` блокирует проверяемый запуск при незавершенном обслуживании. Частичный сбой восстановления требует разбора по отчету.

## Что именно проверено

На исходном Windows 11 проверены отдельные тестовые EXE, а не запуск Claude:

- TUN InterfaceOnly: положительный HTTPS-тест через выбранный виртуальный интерфейс; попытка с физического IPv4 заблокирована; временный WFP-запрет диагностическому EXE заблокировал его соединение.
- TUN + Proxy: HTTPS через выбранный локальный HTTP CONNECT; страна DE; прямой выход и временно запрещенное соединение диагностического EXE не прошли.
- Restore обоих экспериментальных профилей вернул состояние без их ограничений. Действующая настройка Claude/Happ сохранена.
- Офлайн проверены планы строгого TUN с ограничением ядра, произвольные названия, переименование/смена индекса, отсутствие интерфейса, неоднозначность, пользовательские порты и отклонение опасных параметров.

Реальный VPN не отключался. Временный запрет диагностическому EXE не является испытанием физического разрыва туннеля. Строгий TUN с настоящим ядром VPN, перезагрузка, новая Windows, UDP/IPv6 и все варианты отказа не объявляются проверенными. Автоматический сетевой тест сейчас использует IPv4 HTTPS; для сети только с IPv6 он не выдает готовность.

## Границы защиты

Защита относится к явно перечисленным EXE и, при необходимости, указанному сетевому ядру. Она не распространяет тег или политику автоматически на всех потомков. DNS через системную службу, существующие системные посредники, WSL, Docker/VM, удаленное выполнение, kernel-mode VPN и административная смена политик требуют отдельной проверки. Не добавляйте системные службы в Programs без понимания общего влияния.

Режим TUN контролирует интерфейс, но не создает VPN и не гарантирует страну провайдера сам по себе. Страну/IP контролирует свежий тест; он не заменяет постоянную проверку шифрования внутри неизвестного VPN-клиента. Строгий endpoint-фильтр ядра ограничивает направления его собственных соединений, но не подтверждает корректность самого VPN-протокола.

Техническая основа: [условия WFP](https://learn.microsoft.com/en-us/windows/win32/fwp/filtering-condition-identifiers-), [постоянство NET_LUID и отличие от ifIndex](https://learn.microsoft.com/en-us/windows-hardware/drivers/network/ndis-network-interface-services). Драйвер отслеживания произвольного дерева процессов и Sandboxie в этот модуль не добавлены.

Не публикуйте пользовательские конфигурации, административные отчеты и резервные копии: в них есть локальные пути, адреса и идентификаторы.
