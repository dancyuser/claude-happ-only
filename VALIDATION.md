# Проверки v3.3.0 и история v3.2.0

## 30 октября 2026: Desktop + Code и исправление диагностики

На исходной Windows 11 x64 машине реальный WFP-захват показал попытки отдельного встроенного Code EXE выйти через запрещенный виртуальный интерфейс. Их блокировал существующий ClaudeProxyOnly. Desktop в то же время имел соединения к локальному Happ.

Внесены HTTP-прокси настройки Code с резервной копией, окружение проверяемого запуска и защита обнаруженных EXE кэша Code. При административном обновлении подтверждены HTTP CONNECT/SOCKS и отрицательные проверки обхода. После исправления транзакции Verify получены STATIC VERIFY PASS, сохранение прежних ключей фильтров и CHECK ONLY PASS на установленной системе. Владелец затем самостоятельно выполнил запрос Code и сообщил об успешной работе. Агент Claude не запускал и не завершал.

Тесты исходников проверяют синтаксис PowerShell 5.1, компиляцию C#, распознавание Cowork-службы, обычную проверку закрытого клиента без AllUsers, сохранение посторонних JSON-настроек, исправление конфликтующего прокси, инвентаризацию разных версий Code и проверку входных параметров. Отдельный fixture-тест подтвердил побайтовый Restore, отказ перезаписать более новую правку и откат первоначально отсутствующего файла. Фикстуры не являются сетевыми тестами самого Claude.

Новый мастер, конфигурационные примеры и Preview проверены без UAC/изменения живой защиты. Автоустановка и новый PinnedIPv4-режим не объявляются испытанными на чистой другой машине. Существующий набор файлов, прошедший UAC до переработки мастера, не является побайтово идентичным финальному v3.3.0: новая упаковка/параметризация проверяются отдельно. Повторного полного Install/Restore финального ZIP на работающем клиенте не выполнялось.

Реальное отключение Happ проверялось в более раннем curl-опыте. После исправления Code новый полный цикл отключения Happ с самим клиентом не подтвержден. WSL/VM/SSH, произвольные дочерние EXE, чистая установка, перезагрузка и ARM64 не объявляются проверенными. Существующая AppID-политика исходной машины не устанавливается автоматически на новом ПК. Личные адреса, SID, конфигурация и журналы в публичный отчет не включены.

## 27 октября 2026: опубликованный v3.2.0

27 октября 2026 года выполнен административный прогон **точного комплекта из GitHub Release v3.2.0**:

`SHA256(Claude-Happ-Universal.zip) = 19f62954f348d81c19455f79f69d2f2166be99c5a6527f838937878195ccd504`

| Этап | Результат |
|---|---|
| Install поверх существующей конфигурации | OK |
| Fix с автоматическим снимком | OK |
| Restore после контролируемых изменений | OK |
| Содержимое конфигурационного файла | Исходный SHA256 восстановлен, уникальная контрольная метка удалена |
| Пять собственных правил Firewall | Сохранённые параметры восстановлены |
| Контрольный новый маршрут и дополнительные WFP-фильтры | Удалены |
| Производственные фильтры и задача Sync | Сохранены; задача включена |
| Предохранительная копия перед Restore | Создана |
| Полная диагностика после Restore | OK; одинаковый IP и выбранная страна выхода |
| UAC-путь проверяемого ярлыка | CheckOnly PASS, код 0, свежий допуск OK |

После отката временный признак обслуживания снят. Для теста не изменялись прокси-расширения Chrome или браузер по умолчанию. **Claude не запускался агентом:** режим CheckOnly остановился перед реальным запуском.

Browser Tamer 6.3.2 уже был установлен до испытания. Его повторная установка или repair не выполнялись; ранее проверены загрузчик и SHA256 официального MSI без установки.

Перед испытанием владелец самостоятельно закрыл работающий клиент. Начальная попытка при открытом клиенте корректно отказала без изменений. Ошибка выбора каталога отчётов в испытательном скрипте также была исправлена до полного успешного прогона; код опубликованного установщика не менялся.

Это проверка обновления/восстановления на существующей конфигурации Windows x64. Чистая установка на другой машине, перезагрузка, сетевое поведение Claude/Cowork, VM и внешних дочерних программ не объявляются испытанными. Личные адреса, SID, конфигурация и исходные журналы в этот отчёт не включены.

README внутри первоначального ZIP отражает отложенный статус на момент его сборки. Этот отчёт фиксирует последующую проверку тех же неизменённых файлов; первоначальный release ZIP и тег не переписывались.
